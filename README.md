# grpc-mojo 🔥

[![CI](https://github.com/nsalerni/grpc-mojo/actions/workflows/ci.yml/badge.svg)](https://github.com/nsalerni/grpc-mojo/actions/workflows/ci.yml)
[![License: Apache-2.0](https://img.shields.io/badge/license-Apache--2.0-blue.svg)](LICENSE)
[![Mojo 1.0](https://img.shields.io/badge/mojo-1.0-orange.svg)](https://www.modular.com/mojo)

**[📋 Compliance report](https://nsalerni.github.io/grpc-mojo/docs/COMPLIANCE.html)** ([Markdown](docs/COMPLIANCE.md)): 70 differential checks against protobuf, python-hpack, hyper-h2, h2spec, CPython sockets, CPython ssl, and grpcio; regenerated by every CI run.

A pure-[Mojo](https://www.modular.com/mojo) implementation of
[gRPC](https://grpc.io), targeting Mojo 1.0.

**Status: v1 — verified against the industry-standard suites.**
All four RPC kinds (unary, server-/client-streaming, bidi ping-pong),
deadlines and cancellation, metadata (ASCII + binary), DNS/IPv6/UDP and
socket timeouts in `net`, and a `protoc` codegen plugin with cross-file
imports, proto3 `optional` presence, and unknown-field preservation.

Correctness is defined by reference implementations and official suites,
not our own tests:

- **Official gRPC interop cases**: 12 canonical cases × both directions
  × h2c and TLS vs `grpcio`: 48/48 (`pixi run interop-official`)
- **h2spec** (RFC 9113/7541 conformance tool): all 146 checks pass
- **Google protobuf conformance suite**: 698/698 binary wire-format
  tests pass (JSON/proto2/editions declared unsupported, skipped)
- **Differential compliance** vs Python `protobuf`, python-hpack,
  hyper-h2/hyperframe, CPython sockets, `grpcio`
  (`pixi run compliance` → [docs/COMPLIANCE.md](docs/COMPLIANCE.md))

Current limits (tracked in [docs/PRIMITIVES.md](docs/PRIMITIVES.md)):
sequential connection handling and recv-driven bidi (Mojo 1.0 has no public
threads/async), and no compression codecs yet (zlib binding pending).

## Layout

Each future standalone repo lives as a self-contained subfolder under
[`packages/`](packages), with its own manifest, tests, README, and license;
`src/grpc` plus the integration harnesses stay at the top level
(see [docs/PACKAGING.md](docs/PACKAGING.md)):

| Package | Home | What | Depends on |
|---------|------|------|------------|
| `mojo-net` | [`packages/mojo-net`](packages/mojo-net) | TCP/UDP sockets, DNS, IPv4/IPv6 over libc FFI | stdlib |
| `mojo-hpack` | [`packages/mojo-http2`](packages/mojo-http2) | HPACK header compression | stdlib |
| `mojo-h2` | [`packages/mojo-http2`](packages/mojo-http2) | HTTP/2 frames, streams, connections | `hpack`, `net`, `tls` |
| `mojo-tls` | [`packages/mojo-tls`](packages/mojo-tls) | TLS 1.2/1.3 streams with strict X.509 and ALPN | `net`, libssl |
| `protomojo` | [`packages/protomojo`](packages/protomojo) | Protobuf wire format + runtime + protoc plugin | stdlib |
| `grpc-mojo` | [`src/grpc`](src/grpc) | gRPC calls, status, metadata, client, server | all of the above |

Each package is standalone-extractable by design — Mojo 1.0 is missing several
primitives gRPC needs (sockets, async I/O, TLS, zlib), and the plan for
contributing those back to [modular/modular](https://github.com/modular/modular)
or as community packages is in [docs/PRIMITIVES.md](docs/PRIMITIVES.md).
Architecture details: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). The
sequenced plan for closing the remaining gaps and shipping the community
packages: [docs/ROADMAP.md](docs/ROADMAP.md).

## Quick start

```sh
# toolchain
curl -fsSL https://pixi.sh/install.sh | sh
pixi install

# standalone checkout only: fetch mojo-net, protomojo, mojo-http2, mojo-tls
# sources into packages/ (a monorepo-style checkout already has them)
python3 tools/fetch_deps.py

# run the tests
pixi run test

# run the example server + client (h2c on :50051)
pixi run example-server   # terminal 1
pixi run example-client   # terminal 2
```

## Example

Generate Mojo from your `.proto` (messages + client stub):

```sh
pixi run python3 -m grpc_tools.protoc -Iexamples \
  --plugin=protoc-gen-mojo=tools/protoc-gen-mojo \
  --mojo_out=examples examples/echo.proto
```

Server ([examples/echo_server.mojo](examples/echo_server.mojo)):

```mojo
from echo_pb import ECHO_SAY_PATH, EchoRequest, EchoResponse
from grpc import Server, ServerContext

def say(req: EchoRequest, ctx: ServerContext) raises -> EchoResponse:
    var resp = EchoResponse()
    resp.message = String("echo: ") + req.message
    return resp^

def main() raises:
    var server = Server("127.0.0.1", 50051)
    server.register_unary[say](ECHO_SAY_PATH)
    server.serve()
```

Client ([examples/echo_client.mojo](examples/echo_client.mojo)):

```mojo
from echo_pb import EchoClient, EchoRequest

def main() raises:
    var client = EchoClient.connect("127.0.0.1", 50051)
    var req = EchoRequest()
    req.message = "hello"
    print(client.say(req, timeout_ns=10_000_000_000).message)
```

## Compliance

Compatibility is measured, not asserted. `pixi run compliance` differentially
tests every package against an established reference implementation —
`proto` vs Python `protobuf`, `hpack` vs python-hpack, `h2` vs
hyper-h2/hyperframe (which raises `ProtocolError` on any violation we emit),
`net` vs CPython sockets, and `grpc` vs `grpcio` in both directions, and
regenerates [docs/COMPLIANCE.md](docs/COMPLIANCE.md) with the results
(currently **75/75 checks passing**). Each package repo also runs its own
slice of the suite standalone. `test/interop/` holds the quicker
grpcio-only interop smoke suite, and [docs/TESTING.md](docs/TESTING.md)
maps out every verification layer (unit, differential, official suites,
benchmarks) and the coverage philosophy.
